# Бизнес-ланчи Москвы

Сайт с картой проверенных бизнес-ланчей Москвы. Пользователи присылают отзывы через форму,
модератор проверяет адрес и публикует заведение на карте. На главной странице — интерактивная
карта на Яндекс.Картах и лента последних отзывов.

## Возможности

- **Карта на главной** (Яндекс.Карты JS API): точки — только заведения, прошедшие модерацию.
  Клик по точке открывает панель с адресом, актуальным составом бизнес-ланча и отзывами.
- **Лента отзывов** внизу главной страницы — самые свежие опубликованные отзывы по всем местам.
- **Форма добавления отзыва** (`/submit`): название заведения, адрес, оценка, текст отзыва,
  состав и цена бизнес-ланча, фото меню (до 3 шт.) и фото заведения/блюд (до 5 шт.). Если
  заведение уже есть на сайте — можно оставить отзыв на него напрямую (без создания дубликата).
- **Проверка адреса через Яндекс.Геокодер**: при отправке формы адрес автоматически
  геокодируется. Если геокодер уверенно определил точку в Москве — заявка уходит в обычную
  очередь модерации. Если нет — заявка попадает в очередь «Требует внимания», где администратор
  вручную уточняет адрес (с повторным геокодированием) перед публикацией.
- **Админка модерации** (`/admin`, защищена логином/паролем):
  - «Требует внимания» — заведения с неоднозначным/неопределённым адресом;
  - «Новые заведения» — заявки, ожидающие первой публикации;
  - «Новые отзывы» — отзывы к уже опубликованным заведениям.

## Стек

Next.js 14 (App Router) + TypeScript + Tailwind CSS + Prisma + Postgres. Яндекс.Карты
(JS API 2.1) на клиенте, Яндекс.Геокодер (HTTP API) на сервере. Фото — Vercel Blob
(загрузка идёт напрямую из браузера, минуя тело серверной функции).

> БД — Postgres (а не SQLite), потому что на Vercel serverless-функции не имеют
> постоянного диска: файл SQLite не переживёт даже один холодный старт. Подойдёт
> любой Postgres — Neon, Vercel Postgres (тоже на Neon), Supabase, ваш собственный сервер.

## Запуск локально

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env` и заполните переменные:

   ```bash
   cp .env.example .env
   ```

   - `DATABASE_URL` — строка подключения к Postgres. Для локальной разработки проще
     всего использовать ту же облачную БД, что и в проде (Neon/Vercel Postgres — бесплатного
     тарифа достаточно), либо поднять Postgres локально.
   - `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` — ключ JS API Яндекс.Карт (без него карта на главной
     покажет заглушку с инструкцией).
   - `YANDEX_GEOCODER_API_KEY` — ключ HTTP Геокодера Яндекс (без него адреса не проверяются
     автоматически и все заявки уходят в очередь «Требует внимания» для ручной проверки).
     Ключи можно получить в [кабинете разработчика Яндекса](https://developer.tech.yandex.ru/).
   - `ADMIN_LOGIN` / `ADMIN_PASSWORD_HASH` — логин и bcrypt-хеш пароля администратора.
     Хеш можно сгенерировать так:
     ```bash
     node -e "console.log(require('bcryptjs').hashSync('ваш-пароль', 10))"
     ```
     ⚠️ Next.js разворачивает `$переменные` в `.env` (dotenv-expand), а bcrypt-хеш
     содержит символы `$` — экранируйте их обратным слэшем:
     `ADMIN_PASSWORD_HASH="\$2a\$10\$..."`, иначе значение обрежется и логин не сработает.
   - `SESSION_SECRET` — любая длинная случайная строка для подписи сессионной cookie.
   - `BLOB_READ_WRITE_TOKEN` — токен доступа к Vercel Blob (хранилище фото). Локально нужен,
     только если тестируете загрузку фото; получить можно, создав Blob-хранилище на Vercel
     (Storage → Create Database → Blob) и выполнив `vercel env pull`.

3. Примените схему к базе данных (создаёт таблицы; миграций как таковых нет —
   `prisma db push` синхронизирует схему напрямую, это же происходит автоматически
   при каждой сборке на Vercel, см. `package.json`):

   ```bash
   npx prisma db push
   ```

4. (Опционально) заполните базу демо-данными:

   ```bash
   npm run seed
   ```

5. Запустите dev-сервер:

   ```bash
   npm run dev
   ```

   Сайт будет доступен на http://localhost:3000, админка — на http://localhost:3000/admin.

## Деплой на Vercel

1. **Создайте Postgres-базу.** Проще всего — прямо в проекте на Vercel: вкладка
   **Storage → Create Database → Postgres** (это Neon под капотом). Vercel сам подставит
   переменную подключения в проект.
2. **Создайте Blob-хранилище для фото.** Там же, во вкладке **Storage → Create Database →
   Blob**. Vercel сам добавит переменную `BLOB_READ_WRITE_TOKEN` в проект.
3. **Импортируйте репозиторий** на [vercel.com/new](https://vercel.com/new) — выберите
   GitHub-репозиторий и ветку с этим кодом. Next.js определится автоматически.
4. **Задайте переменные окружения** проекта (Project → Settings → Environment Variables):
   `DATABASE_URL` (если Storage не подставил её сам — под именем `POSTGRES_URL` или
   `DATABASE_URL`, переименуйте под `DATABASE_URL`, если нужно), `NEXT_PUBLIC_YANDEX_MAPS_API_KEY`,
   `YANDEX_GEOCODER_API_KEY`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`.
   Для `ADMIN_PASSWORD_HASH` в веб-интерфейсе Vercel экранировать `$` не нужно (это не shell) —
   вставляйте хеш как есть, например `$2a$10$...`.
5. **Deploy.** Команда сборки (`prisma generate && prisma db push && next build`) сама создаст
   таблицы в свежей базе при первом деплое.
6. (Опционально) наполните базу демо-данными с вашей машины:
   ```bash
   vercel env pull .env.production.local
   DATABASE_URL=$(grep DATABASE_URL .env.production.local | cut -d= -f2- | tr -d '"') npm run seed
   ```

## Структура данных

- `Restaurant` — заведение: введённый и распознанный геокодером адрес, координаты, точность
  геокодирования, статус (`PENDING` / `NEEDS_ATTENTION` / `APPROVED` / `REJECTED`).
- `Review` — отзыв: автор, оценка 1–5, текст, состав бизнес-ланча и цена на момент отзыва,
  до 3 фото меню (`menuPhotos`) и до 5 общих фото (`photos`), собственный статус модерации
  (`PENDING` / `APPROVED` / `REJECTED`).

Заведение появляется на карте только когда `status = APPROVED` и есть координаты; в списке
показывается состав ланча из последнего одобренного отзыва как «актуальный на данный момент».
